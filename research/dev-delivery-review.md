# Rust 沙箱平台生产交付与上线验收审查

本稿供详细开发方案合并使用。输入为已有预研、用户确认的企业多租户与非可信代码、公有云从零部署；产品必须带独立身份认证，也能对接既有统一身份。采用 Ponytail：只建设兑现已承诺产品行为必需的组件，安全、恢复、可运维性和用户要求的八项能力均不可裁减。

本文给出开发目标和验收方法；项目尚未实现、压测或通过安全验收。不能把完成本文等同于系统已经可上线。调研日期：2026-10-03。

## 1. 最小但完整的生产范围

第一版面向一个公有云、一个地域、一套通过认证的 Linux x86_64 运行时组合。若云托管集群的运行时与CNI组合没有已支持配置，固定使用自管上游Kubernetes与Kata/Cilium，并承担其安装、补丁、etcd、证书和升级维护。控制组件具备多故障域部署，工作节点使用支持 KVM 的受控机型；一个沙箱对应一个 Kata Pod/VM。一个实例一个持久工作区，应用根文件系统可重建。供其他微服务调用的完整 REST API、OpenAPI 和机器身份授权是首批交付，不等前端完成才补接口。

“可上线”限定为这一配置的生产产品。通用多云、任意镜像任意权限、无损保留任意进程内存、在线迁移、多卷应用一致性、自动跨地域容灾均不应通过模糊描述变成隐性承诺。当前明确范围内的八项能力必须全部交付。

| 自研或复用 | 第一版决策 | 防止复杂化的边界 |
| --- | --- | --- |
| 产品服务 | 一个 Rust crate，`api`、`worker`、`gateway` 三个进程角色 | 不按菜单拆八个微服务；按故障与流量边界部署 |
| 状态与任务 | PostgreSQL 事务、约束、任务表、租约、outbox | 不增加 Redis、Kafka、Temporal；不构建通用工作流 DSL |
| 调度 | 产品层做租户配额/有界排队；Kubernetes 做节点调度 | 不自研节点调度器；业务 DB 是期望状态唯一来源 |
| Kubernetes 对象 | 直接管理 Pod、PVC、Service、网络策略等资源 | 不创建镜像业务数据库的 Sandbox CRD，不提前实现多运行时 provider trait |
| 隔离 | Kata、containerd、固定宿主镜像和受控工作节点 | 不 fork VMM；不以失败回退 runc 提高“成功率” |
| 用户执行 | Kubernetes exec 进入固定的一次性 runner；平台持久化执行账本 | runner 非可信回执不能证明宿主安全；失联结果未知，不重放；强取消终止整个实例并明确影响 |
| 身份 | 独立模式交付Keycloak；联合模式直连既有OAuth2/OIDC；产品DB负责租户授权 | 不自行实现密码/OAuth；身份provider插件化不等于任意组合均已测试，首版明确只交付这两种模式 |
| 网络 | 一种已验证 CNI + 出站强制路径 | 不同时支持多种 CNI；不暴露原始 K8s 管理能力给业务微服务 |
| 存储 | 一种云 CSI、一种对象存储；复用受支持备份搬运组件 | 不自研块存储、备份去重引擎或快照格式 |
| 可观测 | 云托管或企业现有指标/日志服务；平台封装授权查询 | 没有明确跨集群长周期指标需求，不先部署 Thanos；不自建 SIEM |
| 基础设施 | 云原生 IaC + Helm，与既有 CI/CD 整合 | 若无既有 GitOps 不为该项目另建一套；构建一次，按 digest 晋级 |
| 管理界面 | 八项能力对应的薄控制台；全部走同一产品 API | 不建设独立于 API 的后台写库操作，不做通用拖拽自动化编排器 |

**必要例外：**如果云 CSI 与备份搬运组件的组合在 Kata、目标文件系统、目标恢复环境下不通过实测，先调整存储组合；不能为了保持组件清单简短而隐藏数据恢复风险。复用组件也必须有人承担升级、漏洞和故障响应。

## 2. 八项能力的最小生产实现

| 能力 | 必须实现的交付物 | 可重复验收用例 | 第一版不用建设的扩展 |
| --- | --- | --- | --- |
| 实例详情 | 期望/观测状态、generation、最新观测时间、镜像 digest、规格、配额、工作区、策略应用版本、备份状态、正在进行的 Operation | watch 断开时在规定陈旧阈值内显示 Unknown；删除后旧 worker 不能复活实例 | 任意 VM 硬件配置、在线扩缩容 |
| 监控 | CPU/内存/限流/OOM、磁盘/inode、IO/网络、API 与启动耗时、平台可信来源标识；告警确认/恢复/静默 | 采集器中断显示缺测；越权指标查询失败；日志洪水不阻塞控制 API | 自由 PromQL/SQL、用户上传采集插件 |
| 操作记录 | 受理审计与 Operation 同事务；追加结果；身份、授权、请求 ID、资源、摘要、时间；脱敏和独立归档 | DB 不可写时变更不能假成功；worker crash 不丢受理事实；租户不能改历史 | 自建日志搜索引擎、通用行为分析 |
| 事件 | 持久化规范事件，事件 ID/版本、资源/租户、发生与观测时间、去重聚合；签名 webhook 和失败记录 | 消费重复事件不重复动作；K8s 原生 Event 过期后仍可查平台事件 | 全局总序、恰好一次消息总线 |
| 安全防护 | 身份、RBAC、运行时准入、出入站、资源限制、镜像准入、密钥引用、隔离动作；desired/applied 策略分离 | 两租户与元数据/节点/控制面隔离，覆盖 IPv4/IPv6、DNS和代理绕行；撤权有上限 | 自建杀毒/EDR、承诺 guest 全量系统调用可信审计 |
| 健康诊断 | 固定规则：调度、镜像、卷挂载、OOM、磁盘/inode、DNS、证书、备份过期；证据、时间、规则版本与建议 | 人为制造每个故障；证据过期给 Unknown；检查无权限给 Unsupported | 用大模型打分自动执行破坏动作 |
| 定时与自动化 | 有限动作：启停、备份、诊断、批准的命令模板；IANA 时区、漏跑策略、互斥、截止时间、预算和冷却；运行时重新授权 | 多 worker、时钟偏差、重复事件、DST、禁用账号、过期任务；无风暴或静默补跑 | 通用 DAG、跨系统任意插件执行 |
| 备份 | 固定持久工作卷；备份 manifest；独立对象存储；保留/删除保护；新实例隔离恢复；全量完整性校验与周期恢复证据 | 删除原实例及卷后从对象备份恢复；对象损坏被发现；权限和密钥轮换后可恢复 | 内存快照、多卷一致恢复点、任意数据库应用一致性 |

备份范围默认是工作区和重建实例必需的配置。用户写入根文件系统的临时修改不属于备份，不可通过“全量备份”措辞误导。任意应用的在线文件快照默认只承诺崩溃一致性；需要应用一致性必须提供经过恢复测试的适配器。冻结必须有独立超时解冻机制，不能只依赖 worker 的 finally。

## 3. 从开发完成到可上线还缺什么

以下项目最容易在“生产级方案”里写成名词，却没有实现证据：

1. **三个副本不等于高可用。** 核对副本跨故障域、数据库故障切换、负载均衡、证书/DNS、镜像仓库、出站网关和存储的依赖。控制面健康不证明单个沙箱进程不中断。
2. **PDB 不等于沙箱无损迁移。** PDB 对部分自愿驱逐生效，不能阻止节点故障，直接删除 Pod 也可绕过。每个单副本实例需要明确维护窗口与允许重启策略；节点升级先停止接单，再等待实例自然结束或执行已授权维护重启。不能无依据声称零中断。[Kubernetes Disruptions](https://kubernetes.io/docs/concepts/workloads/pods/disruptions/)
3. **RWO/RWOP 不替代物理隔离。** RWO 允许同节点多个 Pod 使用，RWOP 需 CSI 支持；故障节点的物理写入能力必须由电源或存储 fencing 消除，不能只以 DB 租约和对象删除推导旧写入停止。[Kubernetes 持久卷访问模式](https://kubernetes.io/docs/concepts/storage/persistent-volumes/#access-modes)
4. **恢复脚本不等于恢复能力。** 备份必须离开源卷故障域，并验证在删除源 PVC/快照、替换集群以及升级后仍可恢复；对象锁、生命周期、备份凭据和 KMS 删除策略必须相容。
5. **每 24 小时开始一次备份不能保证 RPO≤24h。** 备份耗时和失败重试会使最新可恢复时间点超过 24 小时。默认每 12 小时启动，最长完成目标 2 小时，12 小时窗口用于重试与告警；吞吐不支持时增加资源或修改承诺，不偷换 RPO 定义。保留策略与执行间隔分别配置。
6. **exec 可用不代表整个执行数据面可扩展。** 通过 Kubernetes exec 转发长连接与输出时，必须测 apiserver/APF、每实例并发、连接清理与带宽。平台 gateway 不能凭自身 CPU 低就宣布健康；计划容量不通过需调整路径并重验。
7. **OIDC 已有不代表多租户授权已有。** 所有列表、输出、文件、下载、备份、会话、审计和 webhook 均需覆盖 tenant/project 授权；tenant_id 不能由调用方任意选择。
8. **返回 202 不代表业务完成。** 创建到可执行的端到端指标必须包含网络策略已应用、卷挂载、隔离和 runner 可用；`Failed/Unknown` 必须可查询和处置。
9. **worker 接管不保证外部副作用只执行一次。** 已执行脚本但回执丢失时保留 Unknown，调用方使用业务幂等；不能盲目重放支付、发送或外部数据写入。
10. **控制 DB 回到历史时点可能撤销历史事实。** 灾备切换需关闭变更、自动任务和新授权，提升 epoch，核对删除墓碑/撤权/执行结果，未知资源隔离。未完成对账前不恢复自动调谐。
11. **镜像可重建依赖镜像仍存在。** 固定 digest 的模板与备份有依赖记录，仓库 GC 不得删除仍被生产实例/备份引用的版本；KMS 的备份解密依赖也要保留。
12. **72 小时稳定不能证明月 SLA。** 压测是投产门槛，正式可用性按连续生产观测计算。演练中不可把节点分区等所有故障阶段从结果统计中删掉。

## 4. 开发里程碑与退出证据

从零公有云部署包括 VPC、集群、KVM 节点、托管 DB、对象存储、身份集成、流水线与值班。已有预研的 5–7 个月估算建立在基础设施可复用条件上，不能原样照搬。

**在自管Kubernetes与独立/联合身份双模式前提下，建议预算：32–42 周、8–10 名核心成员、约 60–90 人月。** 包括 3 名 Rust 后端、1 名运行时/网络/存储工程师、2 名 SRE/平台工程师、1 名 QA、1 名前端，按需增加安全与测试支持；安全审查、产品/设计和公有云支持须有明确可用人力。此为区间估算，第一阶段结束后按测量与差距重估。若确认可复用已支持的云托管底座，基础设施投入可重估；采购、组织审批或供应商缺陷修复不能靠增加应用开发人数消除。

| 阶段 | 日历窗口 | 主要开发任务/依赖 | 退出证据 |
| --- | --- | --- | --- |
| G0：环境与契约冻结 | W1–W3 | 明确云/地域/机型/KVM/CSI、自管底座职责；威胁边界；SLO/配额/持久化语义；API与错误码；双模式身份与服务账号模型；IaC网络/账号/凭据规划 | 签署支持矩阵、OpenAPI草案、ADR、威胁模型、目标负载清单与成本模型；所有必需云配额到位 |

G1 未通过隔离、单写者或恢复门槛时，不继续批量开发依赖该底座的高级功能。若厂商机型不支持 KVM/驱动组合，要改变部署 SKU，不能用本地 Docker 演示作为延期替代。

## 5. CI/CD 和产物定义

每个 release 必须具备：Rust 二进制/OCI 镜像 digest、源码提交、Cargo.lock/构建工具链、SBOM、签名与构建来源、OpenAPI、SQL迁移、Helm/IaC、支持矩阵、升级/回滚兼容说明、测试报告及操作手册。把它们列入一个机器可读 release manifest。源代码归档或 `helm install` 成功不是完整交付。

| 执行时点 | 必需检查 | 阻断条件 |
| --- | --- | --- |
| 每个 PR | `fmt`、`clippy`、编译；领域不变量测试；SQL迁移静态/集成检查；OpenAPI兼容 diff；凭据/依赖/镜像扫描 | 失败、未授权破坏契约、不可解释新增高风险依赖、敏感信息进入产物 |
| 涉及权限/状态/存储的 PR | PostgreSQL真实事务测试；双租户授权矩阵；重复/并发/崩溃点注入；必要负向路径 | 跨租户访问、已受理写入丢失、重复资源/执行、不合法状态进入Running |
| 每夜 | 目标 KVM 预生产上的核心 E2E；小规模租户压力；孤儿资源对账；备份恢复抽样 | 关键流程失败或不能自动清理且无明确原因 |
| 候选版本 | 新安装、N−1→N扩展迁移、N回退N−1、混合进程版本；性能/安全/灾备/升级全集 | 数据不可恢复、旧版读写不兼容、不可回退且未完成向前修复演练、证据不匹配候选digest |
| 生产晋级 | 同一已签名镜像由预生产晋级；配置diff；备份时间点与回退开关；合成探测 | 临时重新构建镜像、未审查配置漂移、前置依赖不满足 |

数据库变更采用 expand→发布兼容代码→数据回填→验证→下一独立窗口 contract。回滚通常是应用镜像回滚，不能默认自动回滚已执行的数据迁移；破坏性 contract 前必须确认旧版本已退出支持窗口并保留恢复证据。每次迁移有锁/超时、耗时估算与中断恢复方法。

不以覆盖率百分比作为安全承诺。对状态机、租户授权、幂等、配额、任务调度、备份和文件边界编写真正能在错误实现上失败的测试；低风险静态展示字段不逐项编写形式化单元测试。

## 6. 必须可执行的测试矩阵

以下是上线前用例编号。每项报告包含 release digest、环境、负载、步骤、时间戳、请求/操作 ID、测量原始数据、结论与缺陷。不能只提供截图或“已通过”。

| 编号 | 场景与注入 | 通过条件/证据 |
| --- | --- | --- |
| SEC-01 | A/B租户，对实例/日志/输出/文件/指标/备份/会话/任务/审计做ID替换、列表筛选和游标复用 | 全部拒绝；响应不泄露对象存在与敏感内容；合法同租户正向路径仍通 |

| IAM-01 | 干净环境安装内置Keycloak，初始管理员、用户邀请/禁用、密码重置、MFA、服务账号、JWKS轮换；外部OIDC重复矩阵 | 无默认明文管理员；账户职责交给Keycloak；租户/项目授权归产品DB；外部身份失败无本地越权回退 |
| IAM-02 | Keycloak备份恢复/升级；externalOIDC不可用；身份模式切换演练；同名用户碰撞 | 原有主体由issuer+subject标识，同名不自动合并；身份切换为有计划迁移而非热开关；用户/服务账号权限不扩张；恢复不复活禁用权限 |
| SEC-03 | 不可信代码访问宿主、控制面、元数据、其他租户、IPv6、DNS/DoH/代理绕行和重定向 | 目标全部阻断；安全策略applied generation可核对；允许的业务目标仍可访问 |
| SEC-04 | privileged/hostPath/socket/设备/hostNetwork字段、未签名镜像、可变tag、runtimeClass篡改 | 产品API及K8s准入双重拒绝；Kata故障时不运行runc |
| SEC-05 | 路径穿越、符号链接/竞态、压缩炸弹、长命令参数、输出洪水、过大文件、恶意webhook地址 | 无逃逸/SSRF；限额/背压生效；控制组件无OOM；结果明确截断或失败 |
| ST-01 | 10000次创建/启动/停止/删除；每个外部副作用前后kill worker | 没有重复卷/Pod、配额泄漏、旧generation复活；未收敛资源有可解释工单状态 |
| ST-02 | 同幂等键并发100次；键相同但请求不同；客户端提交超时 | 相同请求指向同一Operation；不同请求409；没有重复运行或额外扣配额 |
| ST-03 | 同实例并发停止/删除/备份/恢复，旧worker租约失效后继续回调 | 冲突规则固定；过期结果不能覆盖新状态；保留卷不会被晚到删除 |
| ST-04 | watch断开、Kubernetes不可达、DB切换、时钟偏差、worker重启 | 既有负载按既有策略继续；新写入不会假成功；恢复后全量对账收敛 |
| EX-01 | exec已提交后断开网关/apiserver；runner回执前崩溃；调用方重复提交 | Unknown不被误报Failed并自动重跑；调用方能按原execution_id追踪；强取消的实例级影响符合契约 |
| EX-02 | 到达声明的执行并发、长输出、慢消费者、连接超时、终端断开 | Rust网关和apiserver均在预算内；输出有序/游标语义可验证；连接与内存最终释放 |
| VOL-01 | 节点断电、仅控制网络分区、仅存储网络分区、云fencing调用失败 | 未证实旧节点停止写入时禁止新挂载；明确Unknown/阻塞原因；不存在双写 |
| BK-01 | 20GiB实数据写入中备份；源卷/PVC/原CSI快照删除后恢复 | 从独立对象备份创建新实例；manifest/文件校验通过；符合所声明一致性；旧实例未被覆盖 |
| BK-02 | 备份对象缺块/损坏、对象存储拒绝、配额耗尽、KMS拒绝、模板删除 | 不产生虚假Succeeded；失败可诊断；恢复依赖不会被GC；告警触达 |
| BK-03 | 冻结后kill worker；hook超时；跨集群/节点/版本恢复 | 最长冻结TTL内解冻；不死锁；仅通过测试的组合列为支持；目标隔离网络没有自动重跑外部动作 |
| DR-01 | DB PITR到删除/撤权之前，K8s资源仍是新状态 | 自动任务与新授权暂停；旧权限/实例不复活；外部副作用不重复；epoch和对账记录完整 |
| SCH-01 | 调度多副本、重复事件、DST重复/跳过时刻、停机补跑、账号撤权、时钟偏差 | 每逻辑调度点仅一个TaskRun；补跑遵守策略；执行前重新鉴权；无无限循环/重试风暴 |
| OBS-01 | 指标/日志采集链中断、审计归档失败、标签膨胀、单租户日志洪水 | 缺测与故障可见；受理审计规则保持；不影响其他租户；容量预算受控 |
| REL-01 | 旧新版本混跑、数据库扩展迁移、切回旧版本、网关rolling | 无契约/数据兼容破坏；既有长连接按期限完成或明确可重连；Operations继续收敛 |
| OPS-01 | 值班人员仅凭手册轮换TLS/OIDC/KMS、隔离租户、恢复DB/实例、回退发布 | 不依赖开发者口头指令；手工步骤/时长完整计量；关键恢复符合目标 |
| INF-01 | 丢失单个控制节点、etcd成员替换/全量恢复、CNI控制组件重启、节点证书轮换、Kubernetes小版本升级回退路径 | 自管底座控制面保持或按目标恢复；网络策略不fail-open；服务与业务DB重新对账；支持矩阵内版本全部有效 |

安全测试覆盖的是已知边界和攻击路径，不得写成“保证不存在沙箱逃逸”。未知内核/VMM漏洞通过补丁、专用节点、权限收敛、应急隔离和安全响应降低风险。

## 7. 72 小时目标容量验收

容量基线暂按 1000 运行实例、每实例1vCPU/2GiB、单20GiB工作卷。用户真实负载未量化前，这是待冻结的测试规格，不是已采购容量。测试前必须确定实例启动速率、执行并发/频率、会话数、输出吞吐、日志量、IO与备份变化率，否则“1000并发”没有工程含义。

建议冻结以下测试包，G1阶段依据真实调用微服务校准；达不到时削减对外发布规格或扩容，不降安全门槛。

| 维度 | 起始验收负载 |
| --- | --- |
| 租户 | ≥20租户，含一个高耗资源租户，租户间禁止相互影响配额与权限 |
| 实例 | 稳态1000运行；Python/Node/编译/浏览器/持续IO按真实比例混合；真实数据卷而非全空盘 |
| 管理API | 100读QPS、20变更受理QPS；变更含查询之外的真实状态事务；速率可按最终业务目标上调 |
| 生命周期 | 常态创建1次/秒并对应回收；100个并发突发每小时1次；记录排队和容量拒绝 |
| 执行 | ≥100并发执行，平均每秒10次提交；包含5%长执行与大输出；限额内/超限单独计数 |
| 会话 | ≥500常开低流量终端/端口连接；慢消费者与断连重连；单独记录apiserver连接与带宽 |
| 工作区 | 分空闲/50%/90%容量；包含inode密集与顺序IO；备份使用20GiB实际数据样本 |
| 备份 | 备份任务与生命周期竞争，同时执行到配置的并发上限；12h周期覆盖备份与重试容量 |
| 监控 | 15秒采样；记录时序数、样本吞吐、日志字节率和成本，不使用路径/命令作无限基数标签 |

72小时不包含未达标负载的升压准备期。正式计时前至少完成环境预检与6–12小时阶梯升压；正式窗口建议：0–24h稳态及突发，24–48h节点/worker/DB/网络故障注入，48–72h升级回滚、备份恢复与长期资源对账。原始曲线保留完整窗口，故障窗口单独标注并单独评价恢复指标。

验收门槛：

- 无租户越权、数据丢失、双写或任意非幂等脚本自动重放；出现任一项即失败。
- 常规查询P95≤300ms，写入受理P95≤500ms；合格请求的平台错误率≤0.1%，容量范围内的无故429/503算失败，超出声明额度的限流单列。
- 热启动P95≤10s须包含工作区和网络准备；冷启动使用固定镜像和仓库带宽单独测。若CSI建卷瓶颈使目标失败，先改启动SLO/预建卷容量规格，再发布真实指标。
- CPU、内存、连接、队列长度无持续不收敛趋势；24/48/72h复测全量资源账，不存在无法解释的孤儿和配额泄漏。
- 遥测新鲜度P95≤45s；陈旧/失联不显示绿色健康。备份不让已运行实例的IO越过对外承诺。
- 单节点真实故障后，仅在成功fencing和备用容量足够条件下实例恢复目标≤5min；未具备物理fencing时阻塞属于正确安全行为，但不能标记恢复SLO通过。
- 20GiB已用数据从独立备份恢复并校验RTO目标≤30min；取样至少覆盖不同节点、工作区数据特征和最近/较旧备份点。
- 形成每1000实例月度成本模型，包含存储、备份、遥测、带宽、KVM节点冗余与人工，不能只列VM报价。

## 8. SLO、值班与恢复承诺

| 服务面 | 目标/定义 | 告警/运营动作 |
| --- | --- | --- |
| 管理API | 月可用性99.9%；30天约43.2分钟错误预算；从合格请求的平台失败率计算 | 短/长窗口错误预算燃烧告警；预算过度消耗暂停非必要变更 |
| 创建到可用 | 热/冷路径分别；从服务受理到runner、策略、卷均可用 | 队列等待、建卷、调度、拉镜像、VM启动各阶段指标；容量耗尽报警 |
| 执行面 | 已接受执行的结果可查询，输出/取消语义符合契约 | Unknown比例、会话错误、apiserver饱和和网关背压报警 |
| 数据新鲜度 | 指标/状态均带观测时间；P95≤45秒目标 | 不足时标Unknown；采集断流/积压报警 |
| 工作区备份 | RPO≤24h目标；按最新可恢复备份数据时点计算 | 12h调度+完成/重试预算；16h预警、20h紧急、24h违约（最终需结合备份耗时冻结） |
| 单实例恢复 | 20GiB实际数据、独立备份、新卷、校验完成≤30min目标 | 对象存储/CSI/KMS/镜像/备用计算均纳入，按完整时间测 |
| 控制数据库 | 日常故障切换单独测；灾难RPO≤5min、RTO目标≤30min | 若安全对账无法在30min内完成须如实改RTO；不能恢复旧权限换取速度 |
| 故障节点 | 有效fencing+存储可达+备机就绪条件下恢复目标≤5min | 无法确认安全则停止迁移并值班处理；绝不强制双挂载 |

按已验证规模与故障范围对外发布指标。跨可用区/地域恢复涉及存储复制与备用计算，未配置与测试就不在SLA里承诺。控制面跨区多副本也不会把可用区级卷自动变成跨区卷。

值班至少覆盖：API/数据库/任务堆积、未知实例、节点故障、证书、身份服务、备份RPO、恢复失败、异常出口、配额/成本、磁盘/inode、日志/监控容量。每项告警有责任人、严重性、手册、抑制/恢复条件与可执行动作。核心团队人数不自动等于7×24值班充分，应明确一级值班与二线安全/存储支持的排班。

推荐频率：每日备份完整性与任务对账；每周抽样实例恢复；每月覆盖全模板/关键StorageClass的轮转恢复；季度DB灾备和节点/网络演练；内核、运行时、CSI、备份组件大版本升级前重复关键恢复矩阵。

## 9. 上线 Go / No-Go 清单

以下项目均须有证据链接、责任人、验证日期与候选release digest。任一安全/数据完整性项失败，直接No-Go；性能未达标只能通过降低公开容量/修改SLO并重新验收解决，不能带着虚假承诺上线。

- [ ] 部署云/地域/KVM机型、Kubernetes/containerd/Kata/内核/CNI/CSI/备份版本已冻结并有支持矩阵，厂商配额可用。
- [ ] IaC能从空账号/项目创建生产基础设施；最小权限、网络、KMS、对象存储和数据库策略经复核，无手工不可追踪依赖。
- [ ] 自管Kubernetes/etcd/CNI/证书升级、备份恢复与值班全部有证据；不依赖厂商尚未支持的运行时/CNI组合。
- [ ] 内置Keycloak独立模式和externalOIDC联合模式均可安装、升级、恢复；账号生命周期、初始管理员、MFA和服务账号交付完整；模式迁移不产生账号碰撞或越权。
- [ ] 所有八项能力和全部公开API都完成成功、错误、并发、重试、授权负向E2E；两个真实调用微服务已用机器身份端到端接入。
- [ ] 非可信负载强制Kata，网路默认拒绝与出站允许列表实测有效，无runc退回、host特权或跨租户数据访问。
- [ ] 10000次生命周期、租约失效、旧generation、删除墓碑、配额对账、exec结果未知均符合契约。
- [ ] 节点分区与断电已证明单写者；不能fence时产品正确停在阻塞状态并告警。
- [ ] 原卷/原快照丢失后独立备份恢复成功；manifest、权限、镜像与KMS依赖齐全；RPO/RTO经测量。
- [ ] DB灾备安全恢复不会复活已删除实例或旧权限，不重放未知脚本；恢复时间包含对账。
- [ ] 72h声明规模混合压测、安全检查与故障恢复全部通过；没有未解释资源泄漏；apiserver执行数据面通过容量验证。
- [ ] 严重且可利用的已知漏洞、P0/P1缺陷全部关闭；不存在以“风险接受”规避跨租户和数据丢失门槛的例外。
- [ ] API与DB升级/回滚、证书/密钥轮换、节点维护重启完成演练；发布产物签名与digest一致。
- [ ] 控制台和API正确声明停止/重启/强取消的数据与进程影响；无内存恢复和任意应用一致性隐性承诺。
- [ ] 值班、告警、恢复手册、应急隔离、支持联系人、漏洞补丁流程已接管；负责人能独立完成演练。
- [ ] 生产备份/遥测/计算/带宽预算已获确认；放量阈值、容量拒绝、停止新建和回退开关有效。
- [ ] 两个真实调用服务完成生产试运行；错误预算/SLO、租户隔离、成本和支持容量均与正式说明一致。

放量顺序建议：内部合成探针与种子租户→不超过声明容量5%→25%→50%→100%。每级至少经历完整业务峰值及一个备份周期；停止条件包括安全事件、数据不一致、错误预算快速消耗、无法收敛的Unknown与RPO风险。回退首先停止新建/新执行并回退控制服务，保护现有工作区；不能用批量删除沙箱来快速“恢复健康”。
