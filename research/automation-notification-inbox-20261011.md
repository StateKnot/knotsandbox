2026-10-11，按开发表推进 G3-04、G3-07 和 G3-10。本轮交付项目级异常通知收件箱：异常事实持久化、分页与详情 API、幂等已阅确认、SDK 和控制台。G3 工作包仍为开发中，本地通过不等于全产品已上线。

后续增量已完成真实 BFF 异常 ACK 故障链，见[独立验收记录](automation-notification-bff-20261011.md)。以下保留本次功能交付时的验收范围和历史边界，不将后续结果写成当时已经完成。

## 实现与架构边界

正式迁移 0042 从新提交的 FAILED / OUTCOME_UNKNOWN 运行事件派生通知，使用同一事务和唯一键保留首次同类异常。旧迁移 checksum 不变，38 永久保留；不回填既有历史。正常运行事件缺少状态时仍沿原有语义执行，不被新触发器拒绝。异常来源必须与真实运行的租户、项目、版本、状态和因果运行 ID 一致。

通知属于项目。原创建者停用不会使历史异常无人可见；读取和确认分别复用当前 `automations:read`、`automations:write`，同时受已配置的 OAuth scope 合同和数据库 live grant 约束。确认不依赖规则的执行授权，不改变原运行、委派、预算、实例或操作，也不表示实际故障解决。数据库角色只有读取及三个确认列的更新权限，不能插入、删除或修改来源。

来源触发器在现有事件序列分配之后执行；来源与确认统一采用项目事件头 → 通知行的锁序。API 通过只加锁的窄函数取得事件头锁，不获得事件头 UPDATE 权限。等锁及提交前重新检查权限和 token 到期。确认审计保留真实 HTTP 请求 ID，域事件保留原运行因果 ID，使现有自动化来源识别排除确认反馈。

正常能力接口增加独立 `api_features.automation_notifications`，不改变严格版本 1 `automation` 对象。数据库、权限或触发器检查失败会阻止正常 API 启动。三个接口的完整请求、ETag、回执与升级顺序见 [运行合同](../docs/automation-notifications.md)。

控制台提供显式刷新、筛选、分页、详情和输入通知 ID 后确认。丢失回执或无效 2xx 回执保持 UNKNOWN；重载后沿原 key、空对象和原 ETag 核对，不能替换请求。重放前核对当前能力、读取权限和不可变来源；撤权、错项目或身份变化清除旧视图。412 保留原记录，不自动另发确认。

本轮沿现有 Rust 数据库模块、正常身份入口和请求 journal 实现，没有新增外发服务、队列或调度 worker。邮件、短信和 Webhook 尚未实现；持久查询与已阅确认是本轮提供的通知渠道。

这些验收有重叠，不相加为统一覆盖数字。UNKNOWN 来源的部分数据库用例使用合法持久化异常夹具，不证明外部云故障已经发生。新的异常确认没有进行真实 BFF 端到端故障注入；其后端与 SDK 使用真实签名 HTTP 验收，UI 使用 Chrome HTTP 合同验收，范围分开记录。

两个自动化数据库各通过正常 `sandboxd --role migrate` 安装 41 条正式迁移：1..37、39、40、41、42，逐项 checksum 验证，无 38。数据库回归另在各自新库执行相同链。两个临时容器及测试子进程清理已确认；真实浏览器的新测试数据库保留，不删除原开发卷。继续复用 `target/review-low-debug`，约 3.2 GiB，验证后磁盘可用 345 GiB，无需清理缓存。

完整本地记录是 `.local/notification-inbox-20261011/delivery-record.json`，含命令、退出码、日志 SHA、源文件及制品哈希、各套件独立计数、失败保留与清理记录。开发过程的首轮控制台类型检查失败已修复并保留原日志；通过结果来自最终命令，不覆盖失败记录。
