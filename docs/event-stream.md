# 持久事件流

`GET /v1/events/stream` 提供项目事件的 SSE 订阅与断线补读。现有 `/v1/events` 继续用于历史列表；它的时间分页游标不能用于事件流。

直接调用产品 API 时，请求携带 `Authorization: Bearer ...`、`X-Tenant-ID` 和 `project_id`。生产控制台通过同源 BFF 的 cookie 会话发起 `fetch` GET，不持有或发送 bearer，也不读取 HttpOnly cookie；BFF 承担后端 token。两条路径都必须持有当前项目的 `events:read` 权限。可选 `instance_id` 只筛选该实例或其操作关联的事件，不替代项目授权。令牌不能放在 URL，原生 EventSource 不作为控制台认证入口。

首次请求的 `replay=latest` 为默认值：从请求读取到的已提交项目头开始，只发送其后的事件；`replay=all` 从序号0开始补读当前保留的历史。只要提供 `Last-Event-ID`，起点由该游标确定，`replay` 不会覆盖断点。响应先发送一个检查点，再发送新数据。需要依事件同步业务的独立消费者，应先保留检查点再核对资源快照并按事件 ID 去重；下述控制台只显示提示，不自动重读或修改业务资源。

| SSE 帧 | ID | JSON 数据 |
| --- | --- | --- |
| `stream.checkpoint` | 签名游标 | `sequence`，十进制字符串 |
| `domain.event` | 签名游标 | `sequence` 与现有 `EventRecord` 元数据 |
| `stream.error` | 无 | 固定 `code`、`retryable`、`request_id`，随后关闭 |
| `: heartbeat` 注释 | 无 | 空闲时约15秒一次；不推进断点 |

事件只包含租户/项目/资源、类型、版本、操作、请求和发生时间等元数据。命令、环境变量、原始provider错误、事件私有payload与执行输出不会放入流。消费者按稳定 `event.id` 去重；这是至少一次交付，不代表消费者的业务动作恰好一次执行。`sequence` 使用字符串，避免JavaScript整数精度损失。

过滤订阅仍按项目序号扫描；其他实例的事件只推进检查点，不发送其内容。检查点必须和领域事件一样保存，避免在繁忙项目中反复扫描已过滤区间。网络接收与业务提交不是同一动作：消费者应在业务处理/保存断点完成后继续读取，自己的事务性收件箱负责将事件去重与业务动作原子提交。

## 控制台实时提示

在“操作 / 事件 / 审计”中选择“事件”，再明确点击“开启实时提示”。进入页面、读取历史快照、普通页面刷新或权限恢复均不会自动订阅。首个检查点确认当前基线；页面显示连接状态、最近观察时间和最多50条事件元数据，按 UUID 去重。断点及缓存仅在当前组件内存中，不写 localStorage；停止连接保留原断点，切换租户、主体、项目、实例、记录类型或退出则取消并清空。

浏览器单次连接的响应头等待上限为10秒，一次读进展等待上限为45秒，总期限为300秒；解析后的迟到结果同样检查原期限。这些上限独立于普通 JSON 请求的20秒限制，不承诺物理 TCP 对端已排空。EOF、断网或期限结束显示停止，只有“从原断点重连”才发送原 `Last-Event-ID`；没有自动重试或重新跳到 latest。400/409/410 清除旧断点及提示，必须点击“重建实时基线”才重新从最新位置开始。401/403/404或权限相关 `stream.error` 清除旧证据并显示拒绝，401还结束本地会话。重建不能补回此前漏读的历史，应另查历史快照。

实时提示不代表操作完成、持续健康或业务恰好一次，不自动操作资源、通知或调用 webhook。`events:read` 是独立的真实权限，不由 `health_diagnostics`、`control_plane_diagnoses` 或尚未实现的通知能力代替；历史分页和实时面板独立，分页读取失败不会自动重连或丢失流断点。

## 提交顺序与恢复

迁移0021给每个项目建立 `event_stream_heads` 和只追加的 `event_stream_positions`。业务事件插入时，触发器在同一事务更新头行，再写序号映射。头行锁持有至提交；另一写入必须等前者提交或回滚后才能取得下一序号。因此，读者不会越过一个尚未提交的较小序号。回滚同时回滚头与映射，不产生已确认但永远缺失的洞。发生时间仍可能倒序，不拿 `occurred_at` 推断提交顺序。

旧数据回填在维护迁移事务内锁定项目与事件表，临时解除源表对owner的FORCE RLS限制，完整读取所有历史项目，然后在同一次提交前恢复FORCE RLS。不会修改旧领域事件或旧迁移校验和。迁移期间需按发布维护流程停止接收写入，禁止把大表回填作为无评估在线DDL。

游标经过共享轮换密钥的HMAC验证，绑定租户、主体、项目、实例筛选、项目epoch、平台 `cluster_epoch` 与序号，最长24小时。恢复控制数据库时必须按灾备流程轮换 `cluster_epoch`；每次重连、读取批次及发送缓存帧前均检查代次，旧分支的断点不能用于新分支，即使新序号追上旧值。使用新的主体接管业务消费，需要显式重建订阅/对账，不得将别人的游标作为授权票据。

签发 API 副本与校验端可能存在时钟偏差。已通过签名验证的游标，其 `issued_at` 最多可以领先校验端当前时间60秒；超过60秒返回 `400 INVALID_CURSOR`。容差只用于未来签发时间，不提供过期宽限：`expires_at` 小于或等于校验端当前时间立即返回 `410 EVENT_CURSOR_EXPIRED`，签发到过期的期限仍不得超过24小时。身份、筛选、代次、序号及实时权限检查保持原合同。

| 情况 | 行为 |
| --- | --- |
| 游标伪造、筛选或主体不匹配 | 400 `INVALID_CURSOR` |
| 游标超过24小时 | 410 `EVENT_CURSOR_EXPIRED` |
| 项目/集群代次变化或历史不完整 | 410 `EVENT_HISTORY_UNAVAILABLE` |
| 游标高于当前已提交头 | 409 `EVENT_CURSOR_AHEAD` |
| 权限撤销、主体/租户/项目停用 | 拒绝重连；已建立流发送脱敏错误后关闭 |
| 数据库/JWKS暂时不可用 | 503或已建立流的可重试错误；不默默丢弃断点 |

客户端不能自动将400/409/410改为“从最新开始”，应显式选择查询当前状态后建立新基线，或从仍保留历史重放。当前领域事件及序号均只追加，尚未启用历史GC；未来归档/保留流程必须保持断点下界与410合同，不能绕过不可变触发器直接删行。

## 背压、鉴权与关闭

每个API副本同时最多64条流；其中每租户最多16条、每租户主体最多4条。配额覆盖整个响应Body生命周期，丢弃Body才释放，不会在响应头发出后释放。扩副本会相应增加集群容量；这些是副本保护上限，不能宣称是全局租户计费配额。

每批最多扫描64条，缓存总预算256KiB。仅在下游拉取时继续读取，没有无限生产队列；超出预算的尾部既不发送也不确认，下次从最后已发序号继续。每帧重新验证JWT和当前数据库权限，空闲时每5秒检查。JWT验证器仍遵守其已配置的JWKS缓存/轮换合同；本地停用与grant撤销不依赖JWT自然到期。单次授权和读取各有10秒上限，不持数据库事务等待客户端读取。

正常流在token到期或连接持续300秒后结束，客户端重新取短期token，携原 `Last-Event-ID` 连接。API收到停止信号先取消流；全局优雅退出最多等待30秒，防止滚动升级被不可读连接永久阻塞。

传输层停止拉取Body时，应用层定时器也可能不被poll，因此300秒不是对恶意慢客户端的TCP强制断开承诺。生产入口必须关闭响应缓冲/转换缓存，并配置、实测下游write-idle超时及单连接/来源上限；客户端暂停读、代理断开、HTTP/2流控和滚动退出属于上线验收。当前本地测试没有把这些真实负载均衡条件标为通过。
